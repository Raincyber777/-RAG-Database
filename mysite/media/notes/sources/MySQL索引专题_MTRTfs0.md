# MySQL 索引专题

## B+ 树索引结构
InnoDB 的 B+ 树索引中，非叶子节点只存键值与子节点指针，全部数据行存放在叶子节点，
叶子节点之间通过双向链表连接。范围查询只需定位起点后沿链表顺序扫描，效率远高于逐行回表。

## 聚簇索引与回表
主键索引即聚簇索引，数据按主键物理有序存放；二级索引的叶子节点保存主键值，
命中后需要回表到聚簇索引取完整行，这就是回表代价的来源。

## 索引失效的常见场景
对索引列使用函数或表达式、发生隐式类型转换、LIKE 以 % 开头的前导模糊匹配、
OR 连接了非索引列，都会导致优化器放弃使用索引转而全表扫描。

## MVCC 多版本并发控制
每行记录维护版本链，事务根据 ReadView 决定可见版本；读已提交每次查询生成新 ReadView，
可重复读只在第一次查询时生成，这就是两个隔离级别的实现差异。
